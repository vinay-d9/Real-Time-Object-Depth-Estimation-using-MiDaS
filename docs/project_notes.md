## 3. Problem Statement

The objective is to estimate the relative depth of objects and regions in a scene from a single RGB image or video frame. A conventional RGB camera records color but does not directly record the distance of every pixel. A monocular depth model can infer useful scene structure from visual cues such as size, texture, perspective, and occlusion.

## 4. Objective and Relevance

This project demonstrates how a pre-trained deep-learning model can be loaded and used for inference without training a new neural network. Relative depth can support scene understanding, robotics research, navigation assistance, augmented reality, indoor analysis, and human-machine interaction. The application is a demonstration and should not be treated as a safety-certified distance sensor.

## 5. MiDaS Information

MiDaS is a monocular relative-depth estimation model from Intel Labs and collaborators. It was trained using multiple depth datasets and multi-objective optimization to transfer across different scenes. The chosen `DPT_Hybrid` variant is a MiDaS v3 model exposed by the official PyTorch Hub interface.

The input is one RGB image. The official transform resizes and normalizes the image and converts it into a PyTorch tensor with a batch dimension. The output is a dense spatial prediction: each output location corresponds to a location in the image after resizing. The prediction is relative inverse-depth-like information. Because the scene scale and camera calibration are not known, it cannot automatically be reported as meters.

## 6. Architecture and Working Principle

The image first enters a DPT-style encoder. The encoder extracts semantic and visual features using a transformer-based backbone. Features at different spatial scales preserve both broad scene context and local structure. A decoder fuses these multi-scale representations and progressively produces a dense prediction. A final prediction head outputs a single depth-related value for each spatial position.

The exact internal layers are defined by the selected MiDaS DPT-Hybrid implementation. This project does not claim that every MiDaS variant has the same backbone; the model name is therefore stated explicitly.

## 7. Preprocessing

1. The input is read with Pillow or OpenCV.
2. OpenCV BGR images are converted to RGB.
3. The official MiDaS `dpt_transform` resizes and normalizes the RGB image.
4. The transform converts the image into a tensor and adds a batch dimension.
5. The tensor is moved to CPU, MPS, or CUDA according to device selection.

The official transform is used instead of manually guessing normalization values. Resizing makes the image compatible with the model's expected processing resolution, while normalization keeps input values in the distribution expected by the pre-trained weights.

## 8. Inference

The model is moved to the selected device and put in evaluation mode with `model.eval()`. Evaluation mode prevents training-specific behavior such as dropout updates. `torch.inference_mode()` disables gradient tracking because this project only performs forward inference. This reduces memory use and avoids unnecessary computation.

## 9. Post-processing

The raw prediction is interpolated back to the original image height and width. This is necessary so the depth map aligns spatially with the original image. Min-max normalization converts the relative prediction range into values from 0 to 255 for display. OpenCV's Inferno colormap converts grayscale values into visible colors. In this project, brighter regions represent larger normalized predictions and are described as relatively closer regions under the inverse-depth visualization convention.

The overlay blends the original RGB image and the colorized depth map. It is a visualization aid, not an additional measurement.

## 10. Application

The Streamlit application accepts image uploads, camera snapshots, and video files. For video, a limited number of frames are sampled so the demonstration remains responsive. Each selected frame follows the same preprocessing, inference, and post-processing pipeline. The interface reports inference time and approximate processing rate.

## 11. Demonstration and Observations

Demonstrations must be generated by running the application or `run_inference.py` on actual images. Useful test scenes include an indoor room, a person, an outdoor road, and multiple objects. Observations should describe visual depth ordering and hardware timing, not invented accuracy values.

## 12. Limitations

MiDaS predicts relative depth and is not automatically calibrated to physical scale. Monocular images contain ambiguous cues, and performance may change with lighting, reflections, transparency, occlusion, unusual camera viewpoints, or small objects. CPU processing can be slow. A calibrated metric-depth model or sensor would be required for dependable meter-level distance estimates.

## 13. Future Improvements

Future work could add metric-depth estimation, camera calibration, object detection plus per-object depth, stereo or depth sensors, faster model variants, GPU or edge deployment, and a continuous browser video-stream component.

## 14. Conclusion

This project successfully demonstrates a complete pre-trained-model workflow. An RGB image or frame is preprocessed with the official MiDaS transform, passed through the pre-trained DPT-Hybrid model in inference mode, resized to the original resolution, normalized, colorized, and optionally blended with the input. The result is useful for qualitative scene understanding and demonstrates practical computer-vision inference without training a model from scratch. Its main constraint is that the output is relative depth rather than guaranteed metric distance.
